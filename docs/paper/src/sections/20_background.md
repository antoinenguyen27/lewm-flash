# 2. Background and literature review

## 2.1 World models that plan in a learned representation

The joint-embedding predictive architecture learns two networks: an encoder that maps an observation to a compact vector (an embedding) and a predictor that predicts the embedding of a future observation from the embedding of the present one. Because the prediction target is an embedding rather than a picture, the model can ignore details that do not matter for what happens next (Assran et al., 2023; Bardes et al., 2024). Conditioning the predictor on actions turns it into a dynamics model, and a goal image becomes a target in embedding space. DINO-WM showed that such a model, built on frozen DINOv2 features, can plan manipulation and navigation tasks zero-shot (Zhou et al., 2025; Oquab et al., 2024); PLDM made the case for planning with latent dynamics learned from reward-free data (Sobal et al., 2025); and V-JEPA 2-AC planned with real robot arms after pre-training on video (Assran et al., 2025). A systematic study found the cross-entropy method the best planner for these models on Push-T (Terver et al., 2026).

LeWM is the system studied here (Maes, Le Lidec, Scieur, et al., 2026). Its encoder is a small Vision Transformer (ViT-tiny; Dosovitskiy et al., 2021) and its predictor a 6-layer transformer conditioned on actions through adaptive layer normalisation (AdaLN; Peebles & Xie, 2023). It is trained end to end from pixels with a regulariser, SIGReg, that keeps the embeddings well spread (Balestriero & LeCun, 2025), and it is evaluated with the stable-worldmodel platform (Maes, Le Lidec, Facury, et al., 2026). Its successors make planning cheaper by changing the model: Fast LeWorldModel retrains the predictor to roll out a candidate in one pass instead of five, halving planning time (Gao & Xu, 2026), and an inverse-dynamics policy trained on top of LeWM replaces search altogether (Nguyen et al., 2026). Planning time in this literature is reported coarsely, as seconds per plan, and is always reduced by changing the model or the algorithm, never by examining how the planner is executed.

## 2.2 Sampling-based planning: CEM and iCEM

The cross-entropy method (CEM) searches by sampling (Rubinstein, 1999; de Boer et al., 2005). It draws many candidate action sequences from a Gaussian distribution, scores each, keeps the best (the elites), refits the Gaussian to the elites and repeats. With learned models it became the standard planner of model-based reinforcement learning (Chua et al., 2018; Hafner et al., 2019; Hansen et al., 2022). LeWM uses it with 300 candidates, 30 elites and 30 iterations per plan, so a plan evaluates 9,000 imagined futures.

The improved cross-entropy method, iCEM, makes CEM sample-efficient (Pinneri et al., 2021). Its most important features for this project are a population that shrinks over the iterations as the search narrows, and the reuse of the best candidates of one iteration in the next. On its benchmarks it needed 2.7 to 22 times fewer samples for the same result. A caution comes from related work: a CEM variant that cut samples a hundredfold by adding gradient steps was only 25% faster than the CEM it replaced, because cutting the number of samples does not cut time unless the cost of each iteration falls too (Huang et al., 2021). Whether iCEM saves time therefore depends on how the planner is executed, which is one of the questions this project answers with data.

## 2.3 Running small AI models fast on a GPU

A GPU runs work as kernels: programs launched by the CPU, each doing one operation (a matrix multiplication, a normalisation) across thousands of parallel threads. Frameworks such as PyTorch launch one or more kernels per operation. For large models this is efficient, because each kernel has enough work to keep the GPU busy. For small models at batch size one it is not: each kernel finishes in a few microseconds, and the time between kernels (the launch itself, the Python code that issues it, and the wait for results) dominates. The roofline model describes performance limited by arithmetic or by memory bandwidth (S. Williams et al., 2009); analyses of small-batch transformer inference show that neither limit applies when latency and data movement dominate (Pope et al., 2023; Ivanov et al., 2021).

Three remedies exist, in increasing order of ambition. CUDA Graphs record a sequence of launches and replay it with less CPU overhead (Gray, 2019). Compilers such as PyTorch 2's `torch.compile` fuse neighbouring operations into fewer, larger kernels (Ansel et al., 2024; Tillet et al., 2019); FlashAttention fuses a whole attention computation into one kernel that keeps its intermediate results on chip (Dao et al., 2022; Shah et al., 2024). The most ambitious remedy is the persistent kernel or megakernel: one long-running GPU program that performs a whole computation, so that there are no launches and no gaps at all (Gupta et al., 2012; Diamos et al., 2016). Megakernels returned in 2025 for language-model inference, where one kernel running a whole Llama forward pass cut latency below a millisecond on an H100 (Spector, Juravsky, Sul, Dugan, et al., 2025; Nrusimha et al., 2025), and compilers that build megakernels automatically followed (Cheng et al., 2026). ThunderKittens, the library used here, exposes the H100's tensor-core instructions and asynchronous memory copies through simple tile abstractions (Spector, Arora, et al., 2025). The H100's thread-block clusters and distributed shared memory, which let neighbouring processors exchange data without going through main memory, are what make a kernel that spreads one small model across many processors practical (Andersch et al., 2022; Luo et al., 2024).

## 2.4 The gap

In robotics, fast sampling-based planning on GPUs is well established with hand-written physics models: MPPI controllers and motion planners reach millisecond rates through custom kernels (G. Williams, Aldrich, & Theodorou, 2017; Bhardwaj et al., 2022; Sundaralingam et al., 2023; Vlahov et al., 2024). For learned world models the field has improved planning speed only by changing the model or the planner. No work has profiled where a world-model planner's time goes when it is executed, measured whether sample-efficient planning saves time in practice, or fused a whole planning loop, with a neural encoder, a transformer rollout, scoring, elite selection and distribution updates over every iteration, into one GPU program. This project does all three, for LeWM.
